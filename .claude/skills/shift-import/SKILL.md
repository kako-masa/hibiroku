# シフト表取り込み

会社から配布されるシフト表は、ひびろく内の表記(日勤/休みなど)ではなく
会社独自の記号で書かれている。ユーザーがそのシフト表(写真・テキスト)を
渡してきたら、この対応表でひびろくのシフト種類に変換し、該当月の
「一括入力」でまとめて登録する。

## マーク対応表(2026年時点)

正本は `src/constants.js` の `SHIFTS` オブジェクト。実行前に必ず
このファイルを読んで最新のマーク(`m`)・ラベル(`l`)と食い違いがないか
確認すること(会社側の記法が変わったり、ひびろく側のシフト種類が
増減している可能性があるため)。

| 会社のマーク | ひびろくのシフト | SHIFTSのキー     |
|:---:|---|---|
| ー    | 日勤   | `dayShift`       |
| 公    | 休み   | `dayOff`         |
| △    | 早準夜 | `earlySemiNight` |
| ▲    | 準夜   | `semiNight`      |
| ●    | 深夜   | `midnight`       |
| オ2   | 遅出   | `lateStart`      |
| -2   | 長日勤 | `longDay`        |
| 有    | 有休   | `paidLeave`      |

## 手順

1. ユーザーが渡したシフト表を読み取り、日付ごとのマークの並びに分解する
   (画像なら読み取り、テキストならそのままパース)。
2. 上の対応表(必ず `src/constants.js` の `SHIFTS` と突き合わせる)を使って、
   各日付をひびろくのシフトキーに変換する。
3. 変換結果を日付順の一覧としてユーザーに提示し、認識に間違いがないか
   確認を取る。
4. 確認が取れたら、ひびろくの「シフト」タブ→該当月へ移動→「一括入力」を
   開き、各日に対応するシフトボタンを選んで「保存する」で反映する。
   - アプリが起動していなければ `npm run dev` 等で起動してから操作する。
   - ブラウザ操作の自動化が使える場合はそれで良いが、ユーザーの実際の
     アカウントに反映させたい場合はユーザーがログイン済みのセッションで
     操作する必要がある(ログイン情報を代わりに入力しない)。
5. 保存後、対象月のカレンダーをスクリーンショット等で見せて反映結果を
   確認してもらう。

## 読み取り精度についての注意(2026-09-17の練習で判明)

会社側のシフト表は元データ(Excel等)が手に入らず、印刷物の写真/スキャンPDF
しか渡されない。1枚に十数人分の行が詰まっているため、そのまま月全体を
一気に読み取ると列がズレやすい。実際に起きた誤り: 「ー」(日勤)が2日連続
すると1本の線に見えて1日分読み飛ばし、以降の日付が1列ずつズレた。

対策:
- 対象者の行を、氏名ラベルと前後の行(上下の氏名)で確実に特定してから読む。
- 月全体を一度に出さず、紙に印刷されている週区切り(赤い縦線、日曜ごと)
  で区切って少量ずつ読み、都度ユーザーに確認を取ってから次の区間に進む。
- 同じマークが連続する箇所(ー ー、公 公、● ● など)は特に誤読しやすいので
  一つ一つ数える。
- 行の右端にある合計欄(日勤◯日、準夜◯日などの集計)があれば、読み取った
  内容の個数と一致するかで検算する。
- スキャンPDFでも画像である以上は同じリスクがあるので、同じ手順で慎重に
  進める。可能ならユーザー本人に読み上げてもらう方が確実。
